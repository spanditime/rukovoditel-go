# Основной пример: ORM

Пример читает одну запись через `orm.Repository[Task]`. Он загружает
metadata сущности 39, регистрирует модель с полем 418 и выполняет
`Get` по явному ID. Запись не изменяется. ID 39 и 418 взяты из
обезличенного probe тестового сервера 3.7; для другой установки замените
их в [main.go](main.go) после проверки своей схемы.

Задайте полный endpoint и credentials через окружение:

```sh
export RUKOVODITEL_ENDPOINT='https://test.example.org/api/rest.php'
export RUKOVODITEL_KEY='...'
export RUKOVODITEL_USERNAME='...'
export RUKOVODITEL_PASSWORD='...'
go run ./examples/orm -item-id 123
```

Код печатает ID и сырое JSON-значение заголовка. Оно может содержать
данные записи; не публикуйте вывод без проверки. Поле `Extra`
сохраняет остальные ключи ответа, хотя пример их не выводит.

`Repository.Insert` и `Update` умеют записывать только
`fieldtype_input` как JSON-строки. У тестовой сущности 39 вставка
требует также других полей и родительскую запись, поэтому этот
пример ограничен чтением. Ограничения и проверенные серверные
сценарии описаны в [RESEARCH.md](../../docs/RESEARCH.md).

Для коллекции после создания `repo` можно выполнить:

```go
rows, err := repo.Query().Search("Title", "пример").RowsPerPage(10).OneResponse(ctx)
```

`OneResponse` возвращает только один ответ сервера. Даже если найдено
10 записей, совпадений может быть больше: параметр страницы не
подтверждён, поэтому метод не выполняет полный обход. `All(ctx)` —
совместимый alias с тем же ограничением. Значения полей в `rows`
остаются сырым JSON.
