# Фасад: две модели, одно подключение

Пример создаёт одно подключение, явно загружает metadata двух сущностей,
регистрирует две Go-модели и читает по одной записи из каждой. Он выполняет
только чтение. `Extra` сохраняет непривязанные ключи ответа; пример их не
печатает.

Перед запуском замените в [main.go](main.go) ID сущностей `39` и `40`,
ID полей `418` и `519` на ID своей установки. `39` и `418` встречались на
тестовом сервере 3.7; пара `40`/`519` здесь только пример настройки второй
модели и не заявлена как схема того сервера. Укажите ID существующих записей:

```sh
export RUKOVODITEL_ENDPOINT='https://test.example.org/api/rest.php'
export RUKOVODITEL_KEY='...'
export RUKOVODITEL_USERNAME='...'
export RUKOVODITEL_PASSWORD='...'
go run ./examples/facade -task-id 123 -note-id 456
```

`Refresh` обращается к серверу и обновляет снимок только по явному вызову.
После регистрации, если привязанное поле удалено или изменило тип,
обновление вернёт ошибку и сохранит прежний снимок.
`Repository[T]` использует уже зарегистрированную модель и то же
подключение. `conn.Client()` даёт доступ к низкоуровневым действиям API.
Вывод содержит значения полей в исходном JSON и может включать данные
записей.
