# rukovoditel-inspect

Read-only команда для разработчика, который подключает библиотеку к своей
установке Rukovoditel. Она показывает сущности, доступные API-пользователю,
поля выбранной сущности и созданные записи (`items`). Для отдельного поля
выводится исходный metadata-объект, для записи — таблица всех ключей ответа.

Задайте полный endpoint и credentials через окружение:

```sh
export RUKOVODITEL_ENDPOINT='https://example.org/api/rest.php'
export RUKOVODITEL_KEY='...'
export RUKOVODITEL_USERNAME='...'
export RUKOVODITEL_PASSWORD='...'
go run ./cmd/rukovoditel-inspect
```

Команда выведет сущности деревом по `path` и запросит ID. На каждом уровне
сущности упорядочены по числовому `sort_order`, затем по ID при равенстве.
Если родитель недоступен API-пользователю, сущность показывается на верхнем
уровне с пометкой об отсутствующем родителе. Вывод содержит ID и имя;
`├─` и `└─` показывают соседние и последние ветки. После выбора она покажет
ID, тип, имя, короткое имя и признаки `is_heading`/`is_required` для полей.
Тип показывается без префикса `fieldtype_`; `■` означает истину, `·` — ложь.
Колонка короткого имени показывает исходный `short_name`, включая
пустую строку; сырой ответ поля доступен при выборе его ID.
Введите ID поля для просмотра его metadata или `i`,
чтобы показать записи этой сущности. В списке записей введите ID для
раскрытия записи; `n` и `p` переходят на следующую и предыдущую страницу,
`r` повторит запрос. `b` возвращает к предыдущему
списку, `q` завершает работу.
Нажатие Ctrl+D также завершает интерактивный ввод.

Список записей — **один ответ сервера** с `rows_per_page=20` по умолчанию.
Если у сущности есть поле с `is_heading`, рядом с ID выводится колонка
с его значением из ответа `select`. Имя колонки берётся из короткого имени
поля либо из полного, если короткое пусто. Значение показывается как JSON;
отсутствующий в записи ключ отмечается `<absent>`. При нескольких heading
полях выбирается наибольший ID, согласно правилу `Schema.HeadingField()`.
Он не гарантирует показ всех записей: полный обход при изменении данных
не проверен, а запредельные страницы на сервере 3.7 могут повторяться.
Начальную страницу можно выбрать через `-page 2`, размер ответа — через
`-rows-per-page 50`. При раскрытии записи таблица показывает ID поля,
`ShortNameOrName`, значение как JSON и `is_required`. Для обычного ключа
поля и `<ID>_db_value` выводятся отдельные строки; неизвестные и системные
ключи тоже остаются видимыми, а неизвестный `is_required` отмечается `-`.

Для прямого перехода к сущности, полю или записи:

```sh
go run ./cmd/rukovoditel-inspect -entity-id 39
go run ./cmd/rukovoditel-inspect -entity-id 39 -field-id 418
go run ./cmd/rukovoditel-inspect -entity-id 39 -item-id 7
```

Команду можно установить как отдельный бинарник:

```sh
go install ./cmd/rukovoditel-inspect
```

Имена сущностей, полей, metadata и записи могут содержать
чувствительные данные; проверяйте вывод перед публикацией. Команда
выполняет только `get_entities`, `get_entity_fields` и `select`. Формы ответов
описаны в [API.md](../../docs/API.md), известные свойства полей — в
[FIELDS.md](../../docs/FIELDS.md).
